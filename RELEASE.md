# Evidence-based tracker release

The cloud repair changes code only. `promos.json` and `history.json` are preserved.
The cloud has no private Mac SQLite database, account list or Apple Mail access.
Passing synthetic tests does not establish that every real receipt was captured.
Do not merge or deploy this repair until the Mac validation below succeeds and CI
is green. No Mail messages need to be moved, trashed or deleted for this release.

## What changed

- Account usage: five unique Eats receipts, or one Eats plus one Ride receipt
  (Lime included). Login access, account usage and individual offer usage are
  independent. Archived accounts are excluded from recommendations. Receipt-completed accounts can still have eligible current offers; usage and promotion completion are independent.
- An account with a usable offer is not labelled Needs checking just because
  another offer is ambiguous. Unmatched discounts do not flag unrelated offers.
- Offers expire at the earlier of explicit terms and 35 elapsed days from the
  first observed offer email. The latter is a labelled policy estimate; it cannot
  prove the activation date. Invalid/missing dates remain reviewable. Reminders
  do not restart the clock. Expiry is distinct from consumed uses.
- Trusted sender/relay matching, direct Lime receipts, original account To
  headers, forwarded dates, updated receipt totals and durable receipt identity
  are corrected. Reclassified untrusted records remain private but do not count
  as confirmed receipts. New deletions retain private hash tombstones; deletions
  predating this schema still rely on the authoritative access list.
- Lifetime and 30-day savings include confirmed Eats and Ride savings.
  Reported savings are reconciled with components, never added to them. Plain
  Uber Cash balance payments are not assumed to be promotional savings.
  Missing Uber One remains an estimate learned from Eats evidence only.
- Public counters reconcile with account/offer records and per-account savings.
  Browser fixtures are deterministic and do not rewrite the user's snapshots.
- Preview never invokes Mail routing. Normal scans/automation are read-only by
  default even if old move/trash flags are true. Optional routing has a second
  explicit opt-in and checks committed evidence. The Inbox now uses the full
  receipt lookback, covering the former 35–90-day discovery gap.
- Imports create consistent, owner-only SQLite backups including WAL data.
  Private verification reparses a copy twice and reports unresolved evidence.
- Pushes validate without deploying. Pages deployment requires manual dispatch
  on main, private-data confirmation and a snapshot generated by this policy.

## Minimal safe Mac validation

Use Node >=22.13 (24 recommended). The commands below run in a new clone, so they
never check out over or overwrite existing local code fixes. Replace the two
private paths with the existing database and authoritative access CSV paths.
Do not paste private files into chat or commit them.

1. Pause the existing hourly agent if installed; this prevents the OLD updater
   from moving mail or racing verification. This changes no Mail messages:

   ```bash
   launchctl bootout "gui/$(id -u)" "$HOME/Library/LaunchAgents/com.nadzz07.uber-promo-tracker.plist"
   ```

   If it is not installed, skip this command. Let any running sync finish. Do not
   remove a lock held by a live process. Preserve the existing clone and its local
   fixes; review them separately before switching automation to released code.

2. Clone the repair branch into a NEW directory, install, and validate a copy:

   ```bash
   git clone --branch fix/tracker-evidence-release https://github.com/Nadzz07/uber-promo-tracker.git uber-promo-tracker-release
   cd uber-promo-tracker-release
   npm ci --ignore-scripts
   npm run validate
   node mac/validate-private-data.js --db "/absolute/path/to/uber-tracker.local.db" --access "/absolute/path/to/account-access.local.csv" --output-dir tracker-validation.local.initial
   ```

   This retains a consistent backup beside the source, leaves the original
   database unchanged, and writes a private report plus a verification copy.
   A nonzero exit means release is blocked. Missing raw evidence must be supplied
   from the original Mail/MBOX export; it must not be guessed or erased. The tool
   checks stored receipts, not mailbox completeness.

3. To discover missing Mail receipts safely, create `tracker.local.env` in this
   NEW clone only. Set the account CSV to the existing private path, point the DB
   at the COPY, preserve your actual mailbox names, and leave safety flags true:

   ```text
   TRACKER_PRIVATE_DB="tracker-validation.local.initial/verification.local.db"
   TRACKER_ACCOUNT_ACCESS="/absolute/path/to/account-access.local.csv"
   TRACKER_READ_ONLY_MAIL=true
   APPLE_MAIL_MOVE_INBOX_RECEIPTS=false
   APPLE_MAIL_TRASH_ARCHIVED=false
   APPLE_MAIL_PROMO_FOLDERS="INBOX"
   APPLE_MAIL_RECEIPT_FOLDER="Uber Receipts"
   ```

   Then run read-only discovery and reverify that copy:

   ```bash
   bash mac/preview-sync.sh
   bash mac/backfill-receipts.sh
   node mac/validate-private-data.js --db tracker-validation.local.initial/verification.local.db --access "/absolute/path/to/account-access.local.csv" --output-dir tracker-validation.local.final
   ```

   These scans read Mail, write only the copied DB/private local exports, and do
   not move/delete messages. They require Apple Mail Automation permission. The
   default historical window is 3650 days; extend it if older receipts exist.
   Include any other real receipt mailbox in a separate read-only MBOX import.

4. Review `tracker-validation.local.final/report.json` and the generated masked
   accounts/offers against known orders. Confirm five Eats vs Eats+Ride status
   examples, duplicate/refund cases, earliest offer dates, and explicit receipt
   savings. The report must have zero receipts without reparseable evidence and
   no unexplained missing accounts/orders. Purchased Uber Cash must stay separate.
   If historical raw messages were not retained in SQLite, import a read-only
   MBOX export into the copied DB and rerun validation with a NEW output directory.
   Do not deploy while a discrepancy remains.

## Merge and publish after validation

Once Mac evidence is verified and all PR checks pass, merge the code PR. In the
NEW release clone, fetch and switch to main only when its tracked status is clean:

```bash
git status --short
git fetch origin
git switch main
git pull --ff-only origin main
cp tracker-validation.local.final/promos.json promos.json
cp tracker-validation.local.final/history.json history.json
npm run validate
npx playwright install chromium
npm run test:browser
npm run build
git add -- promos.json history.json
git commit -m "Regenerate tracker from verified private receipts"
git push origin main
gh workflow run pages.yml --ref main -f private_data_verified=true
```

Only the two sanitised JSON files are committed. Do not force-push. Keep all local
DBs, backups, raw exports, validation reports and access lists private. Protect
main with required CI checks; if branch protection requires data PRs, publish
those two files through a separate data branch/PR instead of pushing main.

Wait for the Pages workflow to pass and verify the live dashboard, account
filters, status counts and receipt-backed savings at
https://nadzz07.github.io/uber-promo-tracker/. No deployment is considered verified
until that workflow AND the live checks pass.

After release, keep the original database and backups. The tested copied database
can become the new private source by setting `TRACKER_PRIVATE_DB` in the NEW
clone to `tracker-validation.local.final/verification.local.db`. Do not overwrite
or erase the original. Resolve any pre-existing Mac code changes before retiring
its old automation. Reinstall automation from the new main clone only after a
successful read-only preview; its Mail safety switch must remain true. Hourly
syncs push safe data; Pages publication is a separate verified manual action.

## Cloud verification limits

The cloud can verify parser/SQLite/synthetic import regressions, public privacy,
mobile/desktop Chromium flows and the build. Apple Mail scripting, actual mailbox
completeness, real monetary totals, remote CI, PR review/merge and live deployment
need their own evidence. No real-data or deployment claim follows from local
synthetic tests. The manual deployment confirmation is an operator assertion,
not a cryptographic attestation that Mail was complete.

## Incremental sync and large private archives

Normal scans skip a message body only when its Message-ID, original account,
received date and committed parser-code fingerprint match the private database.
Changed messages, new messages and parser-code changes are reprocessed. Set
`TRACKER_FULL_RESCAN=true` for an intentional complete reparse. The account CSV
from `tracker.local.env` is exported to the importer; a missing configured CSV
blocks sync rather than allowing excluded accounts to return. Synthetic tests
run without the owner's private configuration in their environment.

For large historical mailboxes, Mail's **Export Mailbox** action can create a
read-only local MBOX copy without changing messages. Keep that export private.
`parseMboxStream` supports an awaited `onMessage` callback for bounded-memory
consumers. The full original export remains evidence even when a verification
copy stores the decoded visible message text. Never treat a partial export as a
complete mailbox. Match exported Message-IDs to live metadata before release.

Optional receipt filing and Archived-account Bin routing require their separate
explicit opt-ins and `TRACKER_READ_ONLY_MAIL=false`. Their plans and results are
retained in owner-only `mail-routing.local.*` directories. Bin routing uses an
explicit, unique recoverable mailbox and fails closed when unavailable; it never
uses Mail's delete command or empties Bin.
